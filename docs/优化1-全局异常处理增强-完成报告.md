@ExceptionHandler(BusinessException.class)

public ServerResponse handleBusinessException(BusinessException e, HttpServletRequest request) {

## 🎯 使用示例

### 在 Service 中抛出业务异常

```java
@Service
public class TeacherServiceImpl {
    
    public Teacher getTeacherById(Integer id) {
        Teacher teacher = teacherDao.selectById(id);
        if (teacher == null) {
            throw new BusinessException("教师不存在，ID: " + id);
        }
        return teacher;
    }
    
    public void updateTeacher(Teacher teacher) {
        if (teacher.getId() == null) {
            throw new ValidationException("教师ID不能为空");
        }
        teacherDao.updateById(teacher);
    }
}
```

### 在 Controller 中使用

```java
@RestController
@RequestMapping("/api/teacher")
public class TeacherController {
    
    @GetMapping("/{id}")
    public ServerResponse getTeacher(@PathVariable Integer id) {
        // 如果教师不存在，Service 会抛出 BusinessException

        Teacher teacher = teacherService.getTeacherById(id);
        return ServerResponse.ofSuccess(teacher);
    }
}
```

## 📊 对比分析

### 优化前

```java
@ExceptionHandler(Exception.class)
@ResponseBody
public ServerResponse error(Exception e) {
    e.printStackTrace();  // ❌ 使用 printStackTrace
    LOG.error("the error message is:" + "    " + e.getMessage());  // ❌ 日志格式不规范
    return ServerResponse.ofError("服务器出现异常");  // ❌ 错误信息不明确
}
```

**问题**:
- ❌ 所有异常都返回相同的错误信息
- ❌ 使用 `printStackTrace()` 而不是日志框架
- ❌ 没有区分业务异常和系统异常
- ❌ 没有记录请求上下文信息
- ❌ 没有异常追踪 ID

### 优化后

```java
@ExceptionHandler(BusinessException.class)
@ResponseBody
public ServerResponse handleBusinessException(BusinessException e, HttpServletRequest request) {
    String traceId = generateTraceId();
    log.warn("业务异常 [TraceId: {}] [URI: {}] [Method: {}] [Message: {}]",
            traceId, request.getRequestURI(), request.getMethod(), e.getMessage());
    return ServerResponse.ofError(e.getCode(), e.getMessage() + " (错误ID: " + traceId + ")", null);
}
```

**优势**:
- ✅ 异常分类清晰，便于定位问题
- ✅ 每个异常都有唯一追踪 ID
- ✅ 详细的日志记录，包含请求上下文
- ✅ 用户友好的错误提示
- ✅ 使用 Slf4j 日志框架

## ⚠️ 注意事项

### 1. 不要过度使用异常

```java
// ❌ 不推荐：用异常控制正常业务流程
if (user == null) {
    throw new BusinessException("用户不存在");
}

// ✅ 推荐：用返回值表示正常业务结果
if (user == null) {
    return ServerResponse.ofError("用户不存在");
}
```

### 2. 异常信息要清晰

```java
// ❌ 不推荐：信息不明确
throw new BusinessException("操作失败");

// ✅ 推荐：信息具体明确
throw new BusinessException("删除教师失败：该教师还有未完成的课程任务");
```

### 3. 敏感信息不要暴露

```java
// ❌ 不推荐：暴露数据库信息
throw new BusinessException("SQL错误：" + e.getSQLState());

// ✅ 推荐：隐藏技术细节
throw new BusinessException("数据操作失败，请联系管理员");
```
