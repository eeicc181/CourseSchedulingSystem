# 开课任务查询失败 - 故障排查指南

## 🔍 问题现象
前端页面显示：**"查询开课任务失败"**

## 📋 排查步骤

### 1️⃣ 检查后端服务状态

#### 方法1：查看控制台
- 后端应该运行在 `http://localhost:8080`
- 查看控制台是否有启动成功的日志
- 查看是否有错误信息

#### 方法2：浏览器直接访问
打开浏览器访问：
```
http://localhost:8080/classtask/1/0
```

**预期结果**：
- 返回JSON数据
- 包含 `code`、`data`、`message` 字段

**如果无法访问**：
- ✅ 后端服务未启动 → 启动后端服务
- ✅ 端口被占用 → 更换端口或关闭占用进程

---

### 2️⃣ 检查数据库连接

#### 查看后端日志
查找以下错误信息：
- `Connection refused`
- `Access denied`
- `Unknown database`
- `Communications link failure`

#### 验证数据库配置
检查文件：`src/main/resources/application.yml`

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/course_arrangement?useSSL=false&serverTimezone=UTC
    username: root
    password: 你的密码
```

#### 测试数据库连接
```sql
-- 登录MySQL
mysql -u root -p

-- 查看数据库
SHOW DATABASES;

-- 使用数据库
USE course_arrangement;

-- 查看表
SHOW TABLES;

-- 查询开课任务
SELECT * FROM tb_class_task LIMIT 10;
```

---

### 3️⃣ 检查跨域配置

#### 查看浏览器控制台
按 `F12` 打开开发者工具，查看 **Console** 和 **Network** 标签

**常见错误**：
```
Access to XMLHttpRequest at 'http://localhost:8080/classtask/1/0' 
from origin 'http://localhost:8081' has been blocked by CORS policy
```

#### 解决方案
确保后端有跨域配置（通常已配置）：

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("*")
                .allowedMethods("*")
                .allowedHeaders("*");
    }
}
```

---

### 4️⃣ 检查API路径

#### 前端调用
```javascript
// ClassTaskList.vue 第901行
this.$axios.get(`http://localhost:8080/classtask/${this.page}/${semesterBak}`)
```

#### 后端接口
```java
// ClassTaskController.java 第27行
@GetMapping("/classtask/{page}/{semester}")
```

**确认**：
- ✅ 路径一致
- ✅ 参数顺序正确
- ✅ 端口号正确（8080）

---

### 5️⃣ 检查数据表

#### 验证表是否存在
```sql
USE course_arrangement;
SHOW TABLES LIKE 'tb_class_task';
```

#### 查看表结构
```sql
DESC tb_class_task;
```

#### 查看数据
```sql
SELECT COUNT(*) FROM tb_class_task;
SELECT * FROM tb_class_task LIMIT 5;
```

**如果表不存在或无数据**：
- 导入数据库脚本：`database/db_course_arrangement.sql`
- 或手动添加测试数据

## 🔧 快速修复方案

### 方案1：重启服务
```bash
# 停止后端
Ctrl + C

# 重新启动后端
mvn spring-boot:run

# 或使用启动脚本
start-simple.bat
```

### 方案2：检查端口占用
```bash
# Windows
netstat -ano | findstr :8080

# 如果端口被占用，杀死进程
taskkill /PID <进程ID> /F
```

### 方案3：清理重启
```bash
# 清理Maven缓存
mvn clean

# 重新编译
mvn compile

# 启动
mvn spring-boot:run
```

## 🆘 仍然无法解决？

### 收集以下信息：

1. **后端日志**（最后50行）
2. **浏览器Console错误**
3. **Network请求详情**
4. **数据库查询结果**

### 检查清单：

- [ ] 后端服务已启动（端口8080）
- [ ] 前端服务已启动（端口8081）
- [ ] MySQL数据库已启动
- [ ] 数据库名称正确：`course_arrangement`
- [ ] 表 `tb_class_task` 存在
- [ ] 表中有数据
- [ ] 跨域配置正确
- [ ] 防火墙未阻止端口
