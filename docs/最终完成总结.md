## 📦 已完成功能详情

### 1. 教室利用率分析系统 ✅
**访问路径**: `/classroom-utilization`

#### 功能特性
- 📊 6个统计卡片（总教室、空闲教室、平均利用率等）
- 📈 4个可视化图表（利用率统计、状态分布、热力图、趋势）
- 🔍 多维度筛选（学期、教学楼、搜索）
- 📅 课表查看功能
- 📥 数据导出（CSV格式）

#### 技术实现
- 后端：`ClassroomUtilizationVO.java` + `ClassroomUtilizationController.java`
- 前端：`ClassroomUtilization.vue` (1500+行)
- API：3个端点

---

### 2. 教师工作量统计系统 ✅
**访问路径**: `/teacher-workload`

#### 功能特性
- 📊 4个统计卡片（教师总数、授课教师、平均课时、超负荷人数）
- 📈 2个可视化图表（Top20排名、负荷等级分布）
- 👤 教师详情查看
- 📚 课程列表展示
- 📥 数据导出

#### 工作负荷等级
- **轻负荷**: < 8课时/周
- **正常**: 8-16课时/周
- **重负荷**: 16-20课时/周
- **超负荷**: > 20课时/周

#### 技术实现
- 后端：`TeacherWorkloadVO.java` + `TeacherWorkloadController.java`
- 前端：`TeacherWorkload.vue` (550+行)
- API：2个端点

---

### 3. 课程冲突检测系统 ✅
**访问路径**: `/conflict-detection`

#### 功能特性
- 📊 4个统计卡片（总冲突、教师冲突、教室冲突、时间冲突）
- 🔍 3种冲突类型检测
- 📋 冲突列表展示（可展开详情）
- 💡 解决建议提示
- 🎯 按类型筛选

#### 冲突检测算法
1. **教师冲突** - 检测同一教师同一时间的多个课程安排
2. **教室冲突** - 检测同一教室同一时间的多个课程占用
3. **时间冲突** - 检测同一班级同一时间的多个课程安排

#### 技术实现
- 后端：`ConflictDetectionVO.java` + `ConflictDetectionController.java` (280+行)
- 前端：`ConflictDetection.vue` (400+行)
- API：2个端点
- 算法复杂度：O(n)

---

### 4. 智能排课建议系统 ✅ (后端完成)
**API路径**: `/schedule/suggestion/*`

#### 功能特性
- 🤖 智能时间段推荐（基于教师和班级空闲时间）
- 🏫 智能教室推荐（基于容量和使用频率）
- 📊 适合度评分系统（0-100分）
- 💡 评分原因说明
- 📈 批量建议生成

#### 推荐算法
**时间段评分因素**:
- 教师是否空闲（关键因素）
- 班级是否空闲（关键因素）
- 时间段偏好（上午 > 下午）
- 避免连续多节课
- 课程分散原则

**教室评分因素**:
- 使用频率（空闲优先）
- 容量适配（40-60人最佳）
- 教室属性（设施完善加分）

#### 技术实现
- 后端：`ScheduleSuggestionVO.java` + `ScheduleSuggestionController.java` (350+行)
- API：3个端点（单个建议、批量建议、统计信息）
- 前端：待开发

## 💻 技术栈

### 后端
- **框架**: Spring Boot 2.x
- **ORM**: MyBatis Plus
- **数据库**: MySQL
- **语言**: Java 8+

### 前端
- **框架**: Vue.js 2.x
- **UI库**: Element UI
- **图表**: ECharts 5.x
- **HTTP**: Axios
- **样式**: Less

- `tb_classroom` - 教室信息

- `tb_teachbuild_info` - 教学楼信息
- `tb_teacher` - 教师信息
- `tb_course_info` - 课程信息
- `tb_class_info` - 班级信息
- `tb_class_task` - 排课任务

### 1. 启动后端
```bash
cd CourseArrange
mvn spring-boot:run
```

### 2. 启动前端
```bash
cd UI/coursearrange

```
